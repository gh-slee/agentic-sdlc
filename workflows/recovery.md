# Recovery workflow

Read [core policy](../core/policy.md), [lifecycle](../core/lifecycle.md) and [evidence](../core/evidence.md); preserve stronger project rules.

Inspect repository identity, instructions, Git/diff, state and outstanding external actions. Reconcile stale notes with reality; preserve dirty work and paused ownership. Check whether tests/commits/adoption/push already succeeded. Revalidate affected assumptions, choose earliest incomplete task and checkpoint actual evidence. Durable notes are useful for long work but the initial build-specific document set is not mandatory for every adopting project.
