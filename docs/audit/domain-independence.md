# Domain-independence audit

The same core is installed into five unrelated project substrates: Python CLI/library, TypeScript/React, backend API, infrastructure code and documentation only. Portability tests initialize disposable Git repositories, preserve every original project file byte-for-byte, retain each profile/additional requirement, verify identical distributed bytes and repeat adoption as NOOP. Commands/invariants are configuration, never an installer-chosen stack or automatic shell execution.

Core/roles/workflows contain no reference-project name, finance precision rule, database, frontend framework, deployment platform or tool-specific test command; the structural checker exercises this boundary and rejects a deliberate domain/stack intrusion. Python is used for framework tooling only. Source audit details remain under docs/audit, not the distributed core. Original build checkpoints and source snapshots are not mandatory adoption content.

The source semantic reports are actual analysis of inspected pinned workflow files by the implementing agent. They are not independent QA, automated equivalence proof or a behavioral model evaluation. The adoption review is BLOCKED by the source allowlist; upstream review keeps domain-specific controls local and recognizes the body-fingerprint rule already covered in the core. Synthetic example reports are separately labeled.
