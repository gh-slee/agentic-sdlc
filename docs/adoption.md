# Review and adopt

Requires Git, CPython 3.12+ and the baseline's hash-locked validation environment. This tooling does not impose Python on the adopted application. Use a pinned committed framework checkout; record `git rev-parse HEAD` and `VERSION`. Clone/fetch is a human-controlled source acquisition step, not an installer action.

1. For a new project, initialize Git and create an initial public-safe commit (an empty commit is sufficient). For an existing project, inspect its current instructions, changes and Git state. Preserve local work.
2. From the pinned framework root run `.venv/bin/python scripts/adopt.py discover --target PROJECT_ROOT`. It reads only selected tracked public policy files and hashes them. Private overrides and ignored files are excluded; the project owner must account for stronger private requirements without publishing them. The output includes `inventory_sha256` over its revision and sorted public policy inventory. In an empty repository use an inspected reference with path `@discovery`, that digest and the actual source revision; this is a virtual discovery receipt, not a file to create. It does not prove private policies are absent.
3. Invoke sdlc-adopt-review in the current coding-agent session. Read discovered policy content as evidence, compare it semantically to the baseline, and write a report matching `schemas/review-v1.schema.json` into an ignored local file. Record actual source and framework commits, path hashes, conflicts, preserved controls, profile, specific changes and tests. No API key is needed. Unavailable semantic review blocks adoption rather than becoming a successful scan.
4. Run `.venv/bin/python scripts/check_report.py REPORT.json`, then `.venv/bin/python scripts/adopt.py plan --target PROJECT_ROOT --report REPORT.json > .local/adoption-plan.json`. Review the entire report, proposed paths and `files` digests. Resolve policy conflicts with the human. READY_FOR_REVIEW is not approval. A project publication allowlist may forbid these additions even if installation is technically possible.
5. Once the exact plan is authorized, compute `shasum -a 256 .local/adoption-plan.json`, then run `.venv/bin/python scripts/adopt.py apply --target PROJECT_ROOT --plan-file .local/adoption-plan.json --reviewed-plan-sha256 REVIEWED_DIGEST`. Supplying the digest acknowledges reviewed bytes; it does not authenticate human consent. The tool revalidates source evidence, revisions and all existing destination bytes.
6. Inspect the diff and `.sdlc/install.json`, run project-required checks, and deliberately add a short pointer to `.sdlc/agentic-sdlc/core/policy.md` in the project's own instructions if appropriate. That pointer edit is manual and reviewed; existing AGENTS.md is never changed automatically. Open a new desktop project chat to verify actual skill discovery; file tests cannot prove a particular session loaded them.

Installation adds `.sdlc/agentic-sdlc/` and three `.agents/skills/sdlc-*` files plus `.sdlc/install.json`. No existing different file is overwritten. Matching existing bytes are kept. Repeating a valid plan against the same unchanged state returns NOOP. Source HEAD changes require fresh revision-bound review. Only committed framework content is distributed; private state, audit snapshots and initial-build checkpoints are excluded.

For interrupted application, keep the exact reviewed plan. `.sdlc/adoption-pending.json` binds it to revisions and digest. Rerunning can finish matching complete files; partial or different bytes cause refusal. Inspect and preserve partial files before a deliberate repair; do not delete arbitrary files or trust a receipt without matching hashes. Final provenance is written last. No rollback/upgrade engine, multiwriter lock or hostile-process filesystem protection is claimed.
