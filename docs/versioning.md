# Provenance and safe updates

Source `VERSION` follows Semantic Versioning; initial source version is 0.1.0. `.sdlc/install.json` distinguishes framework source version, installed version, resolved full Git commit, Codex adapter version, selected profile/requirements and SHA-256 for every distributed path. Custom project files remain separate. A version string alone does not establish source identity.

Updates in v0.1.0 are manual and reviewed. Inspect the installed manifest and hashes before fetching a chosen upstream revision in a separate baseline checkout. Compare old/new managed trees with Git; inspect local managed-file changes and project-owned instructions. Run adoption semantic review for policy conflicts and stronger controls. In a disposable copy/branch, prepare a concrete diff that preserves project changes, update provenance from verified bytes, execute framework and project checks, then request any required policy-change approval. Apply only the reviewed diff through normal Git review. The add-only installer intentionally refuses a changed installed baseline; there is no automatic upgrade command.

Before update, commit or otherwise safely preserve existing work and the old manifest. Roll back a reviewed update using the project's normal Git revert/restore procedure after inspecting later changes; restore the matching old manifest and files together. Never overwrite local customizations or assume Git reverses external data migrations. Revalidate hashes and applicable tests. Check available versions using supported Git tags/log or GitHub releases, compare resolved commits, and distinguish a candidate source version from an actually published release. No v0.1.0 tag/release is implied by the VERSION file.
