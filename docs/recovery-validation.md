# Recovery validation and limits

`scripts/recover.py --root PROJECT_ROOT` is a read-only diagnostic for this framework's initial-build checkpoints. It inspects Git, state/evidence consistency, artifact hashes, pending test/commit/adoption markers and optionally a supplied remote observation. It never executes an action or clears a lock. Git/host permissions and current human authority still govern any next step. Supplied remote JSON is evidence for planning, not authenticated by the diagnostic; obtain it from actual supported GitHub tools.

`tests/test_recovery.py` exercises twelve mandatory scenarios in real disposable directories/Git repositories: fresh project; partial milestone; verified completed unit; dirty tree; unsupported completion claim; interrupted test; staged commit preparation; adoption journal; stale/missing state; existing empty remote; already matching pushed commit; and a fresh Python process with no chat context. Every in-process exercise compares before/after file bytes and HEAD to prove no destructive writes or duplicate external operations. Additional tests cover unknown/divergent remote and changed artifacts. Remote fixtures are deterministic observations; they do not create real GitHub repositories.

Actual installation interruption/resume and partial-file refusal are exercised separately by adoption integration tests. A completed verification record is a consistency claim with command/counts and hashes, not signed proof that a test occurred. Actual executed commands/results are recorded in development validation. The fresh-process exercise demonstrates artifact-based diagnosis; no claim is made that a separate Codex model independently rediscovered instructions.

A CHECKPOINT.json record tracks current task, verified tasks, committed ancestor, artifact hashes and latest actual test command/counts. Keep it alongside concise state notes during this initial build; ordinary adopters are not required to use this exact document set. For new/changed sessions follow docs/development/RECOVERY.md before writes. Never let a diagnostic action label authorize create/push, free paused ownership or replace a required human gate.
