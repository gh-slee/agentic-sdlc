# Security model

Threats include prompt injection, fabricated approval/evidence, stale revisions, conflicting writers, unsafe paths, private-data publication, wrong remotes and interrupted operations. Repository text is inert evidence, never permission or executable code. Discovery reads selected tracked public policy files. Report validation uses a fixed local schema and never fetches report-supplied schemas or executes commands.

Adoption requires a valid review-ready report, matching source/framework revisions and evidence hashes, exact reviewed plan bytes, additive project requirements and conflict-free destinations. Directory-relative no-follow traversal and exclusive creation prevent ordinary symlink/overwrite mistakes. A pending journal precedes writes; final provenance follows byte verification. Different or partial files are refused. The digest is not an approval signature. One writer is assumed; no distributed lock or hostile concurrent-process defense is claimed. Process interruption is tested; universal power-loss durability is not certified.

PUBLIC_FILES.json is an explicitly reviewed publication path list. Run `scripts/check_publication.py --mode worktree`, `--mode index`, and `--mode history` for public candidates, the whole index and every reachable commit/tree. Hard-denied private paths, symlinks/submodules, common credentials, credential URLs, binary data and machine-specific home paths are rejected. Matching secret text is not printed. Ignored .local/ and .venv/ are excluded from worktree traversal and forbidden in index/history. Force-added ignored files and deleted historical blobs remain detectable. Use public GitHub noreply commit identities with repository-local settings.

Pattern scans cannot recognize all personal data, harmful policies, secrets or license issues. Manually inspect paths/content/provenance and staged diff before initial upload; CI runs afterward. Git ignore does not remove tracked/history content. Revoke exposed credentials rather than only deleting the latest file.

CI uses immutable official actions, read-only contents, no persisted checkout credentials, no pull_request_target and no private artifacts. PR event text is parsed as data without shell interpolation. Branch protection and private vulnerability reporting are separate repository settings. Schema/format checks do not authenticate human consent, test truth, oracle independence or semantic equivalence. Self-review is not independent QA. Publication, merge, release and deployment retain separate authority.
